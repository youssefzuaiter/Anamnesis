# Reminders when the app is closed Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Reminders reach the owner's iPhone when no Anamnesis tab is open: a morning digest of tasks due today, and a heads-up shortly before an event or a planned task starts.

**Architecture:** A scheduler inside the app server (started from `src/instrumentation.ts`, Node runtime only, only when ntfy is configured) ticks every minute, works out what is due with a pure planner, claims each reminder in a `ReminderDelivery` row (unique per account and key, so restarts and a second instance never send twice) and publishes it to a self-hosted ntfy server over HTTP. ntfy runs as a compose service bound to localhost; the iPhone reaches it over the owner's tailnet through `tailscale serve` (HTTPS); for instant delivery on iOS ntfy forwards only a message id and a topic hash to ntfy.sh.

**Tech Stack:** Next.js 16 (`instrumentation.ts`), Prisma 7 + Postgres (additive migration), ntfy `binwiederhier/ntfy:v2.34.0` (released 2026-10-24, the newest at least two weeks old), Tailscale Serve, `node:test`, Playwright.

**Spec:** `ROADMAP.md` item 19, the council and the owner's answers of 2026-11-10 (transport ntfy, device iPhone, reach Tailscale, production included).

## Global Constraints

- Free only. No new npm dependency (`fetch` is enough for ntfy).
- Off by default per account (`UserProfile.pushEnabled false`). The scheduler does nothing unless both `NTFY_URL` and `NTFY_TOKEN` are set, and never runs in the Edge runtime.
- Migration additive only: new columns defaulted or nullable, one new table; the previous release keeps working.
- Every query scoped by `userId`; one account's items never go to another account's topic; the topic is generated by the server (`anamnesis-` + 24 lowercase base32 characters), never chosen by the browser.
- Secrets (`NTFY_TOKEN`, ntfy passwords) only in `.env.production`; never sent to the browser, never logged, never in an error message.
- Each reminder is sent at most once (`ReminderDelivery` unique `[userId, key]`); a failed send is retried on later ticks, at most 3 attempts in all.
- No stale catch-up: an event or planned task whose start has passed is never announced. The digest is sent once per local day, at or after the chosen hour, while that day lasts.
- Local time is the app container's `TZ` (set by ops to the host's zone); no per-user time zone.
- Keys: `digest:YYYY-MM-DD` (local date), `event:<id>:<start ISO>`, `task:<id>:<start ISO>` (a moved start is a new reminder).
- Copy: digest title `Due today`, body `A, B, C` (at most 5 titles, then `and N more`); start title `Starts in N min` (N rounded up, at least 1); with titles hidden the bodies are `N tasks due today` / `1 task due today` and `An event` / `A planned task`. Test notification: title `Anamnesis`, body `Reminders reach this device.`
- Settings copy (card heading `Reminders on your phone`): checkbox `Send reminders to my phone`; select `Before events and planned tasks` with 5, 10, 15 (default), 30, 60 minutes; select `Tasks due today` at 06:00 to 12:00 (default 08:00); checkbox `Show titles` (default on) with the line `iOS can hide them on the lock screen: Settings › Notifications › Show Previews.`; button `Send a test`; not configured: `Phone reminders are not set up on this server. See “Phone reminders” in ops/README.md.`
- Retention: delivery rows older than 30 days are deleted by the tick.

## Review Focus

1. The Mac sleeps through 08:00 or an event start, or the app restarts mid-minute: the digest arrives once on waking (same day), the missed start never arrives, nothing twice (Task 1, Task 4).
2. Two schedulers at once (a dev reload, the old and new containers during a deploy): each reminder once (Task 4, two ticks racing).
3. ntfy down, wrong token, slow: a tick never throws out of the scheduler, retries stop after 3, the last error is shown in settings without the token, the next tick still runs (Task 3, Task 4, Task 5).
4. `TZ` unset or a clock change day: the digest date and hour follow the container's zone; a 02:30 local start that does not exist is handled by `Date` (Task 1 with a DST case, Task 7 checks `TZ` in the image).
5. Push turned off, an account deleted, a trashed or done task, an imported event, another account's items: none of them sends anything to this topic (Task 4).
