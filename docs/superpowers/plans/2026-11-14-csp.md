# Content-Security-Policy header Implementation Plan

**Goal:** Every page the app serves carries a Content-Security-Policy that stops injected scripts from running, while the app, its maths (KaTeX) and the theme script still work. Shipped in two steps in one pull request: report-only first (the measurement), then enforcing once the browser suite shows no violations.

**Architecture:** `src/proxy.ts` (Next 16's proxy convention) generates a fresh nonce per request, sends it to the rendering in an `x-nonce` request header, and sets the policy on the response. The root layout reads the nonce and applies it to the one inline script (the theme script); Next applies it to its own framework scripts. Because a nonce must be unique per request, every page becomes dynamically rendered (Next's guide, and the layout reads headers). Policy text is a pure function in `src/lib/csp.ts` so its rules are unit-tested.

**Spec:** ROADMAP item 30: "Content-Security-Policy header (S, security). The app sends none, and notes now render maths and code. Read the CSP guide first. The inline theme script needs a nonce or a hash, and KaTeX's stylesheet and fonts must keep loading. Start in report-only mode to see what it would block, then enforce; the e2e suite must pass under it."

**Money:** none.

## Global Constraints
- Scripts: `script-src 'self' 'nonce-…' 'strict-dynamic'`, plus `'unsafe-eval'` in development only (React's debugging needs it; production does not).
- No `'unsafe-inline'` for scripts or style elements, ever.
- Styles: `style-src` for elements uses the nonce; style *attributes* need `style-src-attr 'unsafe-inline'`, because KaTeX writes `style="…"` into the server HTML. Recorded as a deliberate, narrow exception.
- `object-src 'none'`, `base-uri 'self'`, `form-action 'self'`, `frame-ancestors 'none'`, `img-src 'self' blob: data:` (the QR code is a data URL), `font-src 'self'`.
- No `upgrade-insecure-requests`: the local production server speaks plain http on 127.0.0.1, and the directive would break it.
- A client cannot choose its nonce: the proxy always overwrites `x-nonce`.

## Review Focus
1. A nonce reused across requests (it must not be).
2. A page that is static and so carries no nonce: the theme script would be blocked and the page would flash the wrong theme.
3. Report-only versus enforce: the header name for each.
4. Development-only `'unsafe-eval'` leaking into production.
5. The API and static paths excluded from the header.

### Task 1: `src/lib/csp.ts` (pure) and its unit tests.
### Task 2: `src/proxy.ts`, root layout nonce, the report-only measurement with a browser spec that records `securitypolicyviolation` events.
### Task 3: fix every measured violation (no weakening of script rules), then enforce, and re-run the spec.
### Task 4: smoke check sends the header, a record in CLAUDE.md, README and the roadmap.
