# Session list and sign out everywhere Implementation Plan

**Goal:** The person can see where their account is signed in, end any one session, end all the others, or end every session including this one, and the change takes effect on the very next request.

**Architecture:** Sign-in stays a JWT, but the token carries a `sid` naming a row in a new `AuthSession` table, and the Auth.js `jwt` callback (which runs on every `auth()` call, so on every page, action and route) returns `null`, ending the session, when that row is gone. Ending a session is deleting its row. A token with no `sid` (made before this release) is refused once: everyone signs in again after the deploy. No new dependency.

**Spec:** ROADMAP item 27: "Session list and sign out everywhere (S to M, security)."

## Global Constraints
- Additive migration (one new table, cascade from User); the previous release ignores the `sid` claim and keeps working.
- Every query scoped by the session's `userId`; a session id from the browser is ownership-checked (another account's or a missing id is the same refusal).
- Store a device label (browser and OS), never the raw user agent, never an address.
- At most 50 sessions per account, rows idle 30 days are pruned.
- `lastSeenAt` is written at most once per 5 minutes per session.

## Review Focus
1. A revoked session is refused on its next request in pages, server actions and API routes alike.
2. A session of another account cannot be listed or ended, with a forged id.
3. Cost per request of the check (several `auth()` calls per page).
4. Sign-in paths (login, register) create exactly one row; sign-out ends its own row.
5. A token from before this release; a deleted account's tokens.

### Task 1: `lib/device-label.ts` (pure) and tests.
### Task 2: schema, migration, `services/session-service.ts`, integration tests.
### Task 3: `auth.ts` callbacks (`sid` on sign-in, check on every call), sign-out ends its row.
### Task 4: actions, Settings card, e2e (two browsers), export classification, docs.
